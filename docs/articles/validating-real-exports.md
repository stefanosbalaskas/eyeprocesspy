# Validating Real Eye-Tracking Exports

This article is the Python migration of the frozen `eyeprocess 0.11.1` vignette `vignettes/validating-real-exports.Rmd`.

## Why empirical validation is separate from declared support

An adapter can be structurally implemented and exercised with synthetic fixtures without yet being validated against real exports generated by different device models, software versions, export selections, and laboratory conventions. `eyeprocesspy` therefore distinguishes declared support, synthetic-fixture validation, and real-export validation.

## Validate one source

```python
import eyeprocesspy as ep

result = ep.validate_eye_source(
    path,
    vendor="gazepoint",
    spec=ep.format_validation_spec(run_roundtrip=True),
    import_args={"recording_id": "R001", "quiet": True},
    retain_dataset=True,
    case_id="gazepoint-demo",
)
```

The result should retain separate evidence for format detection, adapter-specific findings, canonical validation, schema coverage, source preservation, quality audits, and canonical round-trip comparison.

## Build a validation corpus

```python
manifest = ep.validation_manifest(
    paths=(gazepoint_path, tobii_path),
    vendor=("gazepoint", "tobii"),
    format_family=("gazepoint_analysis", "tobii_pro_lab"),
    software_version=("fixture", "fixture"),
    case_id=("gp-fixture", "tobii-fixture"),
)

corpus = ep.validate_eye_corpus(
    manifest,
    spec=ep.format_validation_spec(run_roundtrip=False),
    import_args={
        "gp-fixture": {"recording_id": "R001", "quiet": True},
        "tobii-fixture": {"recording_id": "R002", "quiet": True},
    },
)

compatibility = ep.format_compatibility_matrix(corpus)
```

## Produce a safe validation bundle

```python
ep.create_validation_bundle(
    result,
    path="gazepoint-validation-bundle.zip",
    include_dataset=True,
    anonymize=True,
    overwrite=True,
)
```

Automated anonymization cannot identify every study-specific disclosure. Review every bundle before sharing it, and do not include proprietary raw exports without redistribution permission.

## Recommended acceptance process

For each vendor and software version, collect multiple de-identified exports with different export selections; record device, firmware, software version, sampling rate, and coordinate configuration; inspect every warning and failed canonical field; verify trial markers, pupil units, fixation provenance, and AOI semantics; retain compatibility evidence with the package release; and promote support from fixture-tested to empirically validated only after the declared empirical requirements pass.
